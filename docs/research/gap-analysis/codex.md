# Tacit gap analysis — Codex analyst

As of **30 October 2026**. Web browsing was available; competitor evidence below is from official sites and repositories.

**Baseline discrepancy:** the brief says `main` at 0.42.0. This repository's local `main` is `539b25661d6fcdbb10dedcfbe8c77b927e9f0cb5`, dated 29 October 2026, and its `package.json` says **0.41.0**. The checked-out branch is `opencode-standalone`, at `a8ef6e6b82d9e813e32ff2ef05f2ce0f1adedb4c`, whose package says 0.42.0. I inspected **local main with `git show` and `git grep`**, without switching branches, and exclude branch-only changes. This is an analysis of the available main baseline, not a certification of an unavailable main/0.42.0 release. Tacit paths throughout refer to that main commit.

## 1. Summary

- **Make a fresh worktree runnable.** Tacit creates isolated worktrees, but I found no first-class project setup/run recipe, ignored-config copying, or port allocation. A developer can launch agents yet still be unable to run their output. Existing worktree control: `cli/tacit.ts`, `headless-runtime/worktree-control.ts`; terminals: `electron/pty-manager.ts`. Conductor has repeatable setup/run actions [33].
- **Finish the review-to-PR loop.** Tacit already commits and pushes; the missing basics are line comments returned to an agent, a Create PR action, and PR/check status. Its diff and Git UI are real, but stop short of that loop: `src/components/RightPanel/DiffContent.tsx`, `src/components/RightPanel/GitContent.tsx`, `electron/git-info.ts`. Conductor and T3 provide substantially more [34,40].
- **Offer a clear way back from agent edits.** Canvas snapshots are not source-code checkpoints. Tacit has Git discard/stash and provider-native rewind, but no unified turn-level recovery: `electron/snapshot-history.ts`, `electron/git-info.ts`, `src/terminal/slashCommands.ts`. Claude Code, Conductor, and Hermes explicitly document code checkpoints [13,21,38].
- **Explain effective permissions before starting work.** Tacit has approval cards and provider modes, but no common filesystem/network policy. Its Codex auto-approve launch flag also bypasses the sandbox: `electron/manager-chat/drivers.ts`, `src/terminal/cliConfig.ts`. The gap is consistent, visible control, not total absence of approvals [6,12,43].
- **Build a user-facing shared skills and connections surface.** Tacit already installs its bundled skills into Claude and Codex, and discovers slash commands. That is not an arbitrary user-managed library shared across every supported agent, with connectors and authentication: `electron/skill-manager.ts`, `electron/slash-commands.ts`. Claude/Codex plugins and OpenClaw's shared skills establish a stronger baseline [1,9,25].
- **Expose account readiness and switching.** Model/provider choice exists; a consolidated agent-account login/switcher was not found. Browser identities are a separate capability: `src/components/SettingsModal.tsx`, `src/components/IdentityManagerModal.tsx`, `electron/agent-detect.ts`. Conductor and T3 make provider setup more explicit [35,39,49].
- **Do not put “add memory,” “add history,” “add Git,” or “add a scripting API” on the gap list.** Main already implements workdesk memory and recall, searchable/resumable native sessions, substantial Git controls, and CLI/HTTP/headless operation: `electron/memory-service.ts`, `electron/api-server.ts`, `electron/session-search-index.ts`, `electron/git-info.ts`, `cli/tacit.ts`, `headless-runtime/index.ts`.
- **The remaining weekly-use gaps are discoverability and continuity:** desktop attention notifications, issue-to-task integration, consistent extension setup, and remote interaction. Headless execution and usage sync already exist; an integrated hosted/mobile experience and full settings/history sync do not follow from them: `headless-runtime/index.ts`, `headless-runtime/webhook.ts`, `electron/usage-sync.ts`, `electron/state-persistence.ts`.

**Extensibility qualifications.** Tacit's installer registers its own Claude plugin and links its bundled skills into `~/.claude/skills` and `~/.codex/skills`; `installAllSkillLinks` does not install a universal catalog into every supported CLI. Slash discovery reads Claude/Codex skill roots and Claude marketplace directories. Existing user CLI configuration remains usable, which earns partial credit; there is no general extension installer/editor or MCP connection manager in the inspected settings UI (`electron/skill-manager.ts`, `electron/slash-commands.ts`, `src/components/SettingsModal.tsx`). Internal lifecycle telemetry hooks are not a user-configurable cross-provider hook system (`electron/hook-receiver.ts`).

“Shared” deserves caution everywhere. Codex and Claude expose reusable configuration within their own runtimes, not arbitrary other harnesses [1,9]. Hermes has external skill roots and inherited child tools, but independent profiles are separate scopes [16,20,22]. OpenClaw explicitly shares managed skills across agents, while workspace skills and harness-native capabilities remain scoped; this does not establish universal sharing of every connector with every delegated CLI [25,47]. Conductor and T3 preserve provider-specific configuration [35,41,49]. Herdr supplies an agent-readable operating guide and installable interface mods; those are different from an agent skills/MCP bundle [30].

**Code-workflow qualifications.** Tacit has stage/unstage, commit/amend, push/pull/fetch, discard, stashes, branch operations, merge/rebase/cherry-pick, and merge-state handling. These are implemented, not a README promise (`electron/git-info.ts`, `src/hooks/useGitStatus.ts`, `src/components/RightPanel/GitContent.tsx`). The Diff panel renders changes but has no line-comment submission loop. Searches of the Git UI, preload/API surfaces, and CLI found no first-class PR/CI integration (`src/components/RightPanel/DiffContent.tsx`, `electron/preload.ts`, `src/types/index.ts`, `cli/tacit.ts`). Asking an agent to run `gh` is a workaround, not that interface.

Hydra really creates and cleans up worktrees and merges dispatch branches; ordinary terminals are not automatically isolated just because they are on the canvas (`hydra/src/spawn.ts`, `hydra/src/cleanup.ts`, `hydra/src/cli-commands.ts`). Comparison credit means branch/diff inspection or explicit orchestration, not an invented side-by-side experiment judge. Tacit's canvas snapshot restore restores workspace state; it is not a source tree snapshot (`electron/snapshot-history.ts`, `src/snapshotState.ts`). Git stash/discard and native CLI rewind earn partial recovery credit.

Hermes worktrees have automatic mode and opt-in code checkpoints [21]. Its Git Tasks integration is an **optional community plugin listed in the official catalog**, not a default core UI [46]. T3's “SnapShots” feature is screen capture, not code undo; its actual file rewind is documented separately in the composer, limited to eligible worktree/provider cases [41]. Issue rows require both intake and outward status: imported context alone earns partial credit, including Conductor where the inspected guide clearly proves intake but does not fully specify bidirectional issue-status synchronization [37].

**What workdesk memory actually does.** `getMemoryDirForWorkspace(canvasId)` uses `~/.claude/projects/workspace-<canvasId>/memory`, separate from the path-derived per-worktree directory. `scanMemoryDir` reads Markdown, frontmatter, and links into a visible graph; filesystem watchers refresh it (`electron/memory-service.ts`). The UI has workdesk/worktree/activity scopes and opens memory files for editing (`src/components/RightPanel/MemoryContent.tsx`, `src/components/FileEditorDrawer.tsx`). Notes and manager journal entries update a `MEMORY.md` index (`electron/memory-notes.ts`).

`workspaceSummary` supplies current canvas counts, the ten most recent journal descriptors, and a recall digest. `workspaceMemoryQuery` searches stored names/descriptions/bodies and is open to terminals; journal mutation is manager-gated (`electron/api-server.ts`). The enhanced memory index adds explicit cross-file references and old-date reminders, rather than providing a general semantic index (`electron/memory-index-generator.ts`). This is concrete continuity infrastructure. It does **not** prove that every external CLI automatically ingests every workdesk memory or shares an identical memory policy. The opportunity is to make scope, access, and reuse obvious, not replace the store.

Tacit's deep search includes files and native session contents (`electron/search-handlers.ts`, `src/components/SearchModal/searchProviders.ts`). That does not establish a universal agent-facing semantic code index; launched agents retain their own search tools. Context meters/compaction events are implemented in structured chat, while terminal support depends on the CLI (`src/toolbar/chat/LongRunning.tsx`, `src/terminal/slashCommands.ts`). Usage aggregation across devices is real, but local snapshot/preferences persistence is not full conversation/settings synchronization (`electron/usage-sync.ts`, `electron/state-persistence.ts`). Remote clients attaching to one running server are also distinguished from copying complete state across independent machines [20,29,30,50].

**Safety/control qualifications.** Tacit structured chat passes approval requests to the UI and forwards decisions; its Claude `alwaysAllowed` set explicitly lasts for the current chat, while provider-suggested permission updates may have a broader lifetime (`electron/manager-chat/drivers.ts`). Native CLI rules can persist, but that is not a Tacit-wide allowlist. Terminal auto-approve maps to different provider flags; for Codex it is `--dangerously-bypass-approvals-and-sandbox` (`src/terminal/cliConfig.ts`). Electron's renderer sandbox is not an agent filesystem/network sandbox.

Cost/token history and subscription quota views exist. Worker admission limits concurrency, not dollar spend (`electron/usage-collector.ts`, `src/components/UsagePanel.tsx`, `electron/worker-admission.ts`). Structured chat and tasks expose waiting/finished state; I did not find a general native desktop-notification delivery layer in the inspected main process. Thus attention support is partial, not absent (`electron/telemetry-service.ts`, `src/components/CompletionGlow.tsx`, `src/tasks/useTasksNeedingYou.ts`).

The headless runtime, API, persistence, webhook transport, and container definition are implemented on main. They earn partial remote/off-laptop credit; they do not establish a hosted service, phone approval interface, or in-app scheduler (`headless-runtime/index.ts`, `headless-runtime/api-server.ts`, `headless-runtime/webhook.ts`, `headless-runtime/notification-transport.ts`, `server/Dockerfile`). Herdr remote terminals can run on a server, but a DIY notification mod is not a verified mobile approval client [30]. T3's server/service and scheduled jobs require an available host; they are not evidence of provider-hosted compute [39,42,50].

Tacit masks recognized secret patterns in its retained record/transcript copies and encrypts stored API-key material through Electron safe storage (`shared/secret-mask.ts`, `electron/transcript-keeper.ts`, `electron/main.ts`). This does not guarantee that arbitrary secrets never enter a provider prompt, original CLI transcript, live terminal, image, or screen. The same distinction prevents blanket ✅ ratings for competitors merely offering secret storage or a sandbox [6,12,24,27,36,40]. An audit ✅ here means useful inspectable records, not tamper-proof compliance logging.

## 5. Where Tacit is ahead

- **Mixed-agent coordination with explicit delivery state:** wires, mailboxes, tracked handoffs, and result-oriented Hydra workflows provide more than a collection of independent chat tabs (`electron/wire-send.ts`, `electron/wire-mailbox.ts`, `electron/tracked-handoff.ts`, `hydra/src/dispatcher.ts`, `hydra/src/protocol.ts`). Herdr and T3 also have meaningful orchestration; this is not an exclusivity claim [30,45].
- **Workdesk-level continuity and provenance:** manager journals, searchable recall, terminal transcripts, task progress, and the visible memory/activity surface connect work across agents (`electron/api-server.ts`, `electron/capture-service.ts`, `electron/recall-service.ts`, `electron/memory-notes.ts`, `src/components/RightPanel/MemoryContent.tsx`).
- **A broad implemented foundation:** real Git controls, in-app editing, headless control, and shared project-instruction setup mean many improvements can be incremental (`electron/git-info.ts`, `src/components/FileEditorDrawer.tsx`, `headless-runtime/index.ts`, `electron/project-instructions.ts`). The relevant advantage is the combination on one canvas, not that competitors lack each component.

The website separately links **Herdr TUI**; `/docs` redirects into that TUI documentation. App/core/guide evidence is used for ratings [30]. - **Every `?` cell is unresolved.** In particular: Hermes line-comment review; OpenClaw native PR/CI/diff/editor/checkpoint workflows and full MCP management scope; Herdr's unverified controls/workflows; Conductor plugin/hook/custom-role compatibility, persistent memory, prompt attachments, context meter, usage caps, and notification breadth; and T3 issue-tracker status-out/custom role definitions.
